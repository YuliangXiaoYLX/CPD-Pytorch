# Registration methods

All methods share one probabilistic model and the same expectation-maximization (EM)
loop; they differ in the transform \(\mathcal{T}\) applied to the source points.

## The CPD model

The \(M\) transformed source points \(\mathcal{T}(y_m)\) are the centers of an isotropic
Gaussian mixture with variance \(\sigma^2\). A uniform component of weight \(w\) absorbs
outliers. Each target point \(x_n\) is assumed to be drawn from

\[
p(x) = w\,\frac{1}{N} + (1 - w) \sum_{m=1}^{M} \frac{1}{M}\,
       \mathcal{N}\left(x \mid \mathcal{T}(y_m), \sigma^2 I\right).
\]

**E-step.** The posterior probability that \(x_n\) was generated by \(y_m\) is

\[
P_{mn} = \frac{\exp\left(-\frac{\lVert x_n - \mathcal{T}(y_m)\rVert^2}{2\sigma^2}\right)}
{\sum_{k=1}^{M} \exp\left(-\frac{\lVert x_n - \mathcal{T}(y_k)\rVert^2}{2\sigma^2}\right)
 + (2\pi\sigma^2)^{D/2}\,\frac{w}{1-w}\,\frac{M}{N}}.
\]

The implementation never stores \(P\): it processes blocks of target points and keeps
only \(P\mathbf{1}\), \(P^\top\mathbf{1}\) and \(PX\), which is all the M-step needs
(see [large point sets](large.md)).

**M-step.** The transform and \(\sigma^2\) minimize

\[
Q = \frac{1}{2\sigma^2} \sum_{m,n} P_{mn} \lVert x_n - \mathcal{T}(y_m) \rVert^2
  + \frac{N_P D}{2} \log \sigma^2, \qquad N_P = \sum_{m,n} P_{mn},
\]

which has a closed-form solution for every method below. The value of \(Q\) is
available as `reg.q` and is passed to the callback as `error`.

Points are rows of the arrays, so matrices multiply from the right (`Y @ R`). They are the
transposes of the matrices in the paper, which uses column vectors.

## Rigid

[`RigidRegistration`][cpd_pytorch.RigidRegistration] estimates a rotation \(R\), a
translation \(t\) and, unless `scale=False`, an isotropic scale \(s\):

\[
\mathcal{T}(Y) = s\,Y R + \mathbf{1} t^\top .
\]

The rotation comes from the singular value decomposition of the weighted cross-covariance
of the centered point sets, with a correction that excludes reflections. The
implementation works in any dimension.

```python
reg = RigidRegistration(X, Y, scale=False)  # rigid: rotation and translation only
TY, (s, R, t) = reg.register()
```

Initial values can be given with `R`, `t` and `s`, e.g. to start from a coarse alignment.

## Affine

[`AffineRegistration`][cpd_pytorch.AffineRegistration] estimates a general linear map
\(B\) and a translation \(t\):

\[
\mathcal{T}(Y) = Y B + \mathbf{1} t^\top .
\]

Affine registration can also shear and scale anisotropically, so it can fit shapes
that rigid registration cannot. It is also more prone to degenerate solutions on
symmetric shapes.

## Deformable

[`DeformableRegistration`][cpd_pytorch.DeformableRegistration] moves every source point
by a smooth displacement field,

\[
\mathcal{T}(Y) = Y + G W, \qquad
G_{ij} = \exp\left(-\frac{\lVert y_i - y_j \rVert^2}{2\beta^2}\right),
\]

and adds the motion-coherence regularizer
\(\frac{\alpha}{2}\operatorname{tr}(W^\top G W)\) to \(Q\). The M-step solves

\[
\left(\operatorname{d}(P\mathbf{1})\,G + \alpha\sigma^2 I\right) W
= PX - \operatorname{d}(P\mathbf{1})\,Y .
\]

- `beta` is the width of the Gaussian kernel: points closer than about `beta` move
  together. Larger values give more global, smoother deformations.
- `alpha` weighs smoothness against the fit to the data. Larger values give stiffer
  deformations.

Both are in data units unless `normalize=True` (see [parameters](parameters.md)).

### Low-rank approximation

The M-step solves an \(M \times M\) system, which costs \(O(M^3)\) time and \(O(M^2)\)
memory. With `low_rank=True`, \(G\) is replaced by its `num_eig` leading eigenpairs,
\(G \approx Q \Lambda Q^\top\), and the Woodbury identity reduces every M-step to a
`num_eig` \(\times\) `num_eig` system (Myronenko & Song, 2010, Sec. 4.2). The Gaussian
kernel's spectrum decays quickly, so a few dozen to a few hundred eigenpairs usually
suffice.

The eigenpairs are computed once by randomized subspace iteration (Halko, Martinsson &
Tropp, 2011), until every residual is below \(10^{-6}\) of the smallest eigenvalue kept.
The approximation then differs from the one built from a dense eigendecomposition by about
a millionth of its own truncation error, so the two give the same registration. For large
\(M\) the kernel matrix is never formed: its rows are generated block by block. The
random start is seeded, so results are reproducible.

## Deformable with known correspondences

[`ConstrainedDeformableRegistration`][cpd_pytorch.ConstrainedDeformableRegistration]
adds correspondence priors (landmarks) as in the Extended CPD of Golyanik et al. (2016):
source point `source_id[i]` is pulled toward target point `target_id[i]`.

```python
reg = ConstrainedDeformableRegistration(
    X, Y, source_id=[1, 10, 20], target_id=[4, 12, 30], e_alpha=1e-8
)
```

`e_alpha` is the reliability of the correspondences, from `1e-8` (trusted) to `1`
(weak).

## Convergence

The loop stops after `max_iterations` iterations, or earlier when

- rigid and affine: the objective \(Q\) changes by less than `tolerance`;
- deformable: \(\sigma^2\) changes by less than `tolerance`, as in pycpd;
- any method: \(\sigma^2\) reaches the machine-precision floor, i.e. the source already
  fits the target exactly.

`reg.converged` tells whether the criterion was met before `max_iterations`, and
`reg.iteration` how many iterations ran.
